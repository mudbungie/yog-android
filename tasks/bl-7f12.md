The repo carries its hard-won platform traps in prose beside the code that pays
for them (DESIGN §3's four device findings, §6's two JNI and restricted-settings
traps, bl-2958's three upstream defects). The bl-15bd work added platform facts
that belong in the same ledger and are not there yet:

- **An app's private storage is not executable** (API 29+), and the one
  exception is the native library directory, whose contents are placed at
  install time and cannot be generated. DESIGN §10 states this where the server
  bootstrap needs it; the ledger should carry it as a platform fact, because it
  bounds anything this app might ever write and then run.
- **The accessibility service moved class**, so an operator upgrading rather
  than installing fresh re-enables it in system settings — and meets the
  restricted-settings block a second time. Today this is moot (the
  `applicationId` changed, so every install is fresh), which is exactly why it
  is worth writing down before it stops being moot.
- **A `tests/` integration crate is not wholesale test code to clippy.** Only
  its `#[test]` items are relaxed; a free helper beside them is judged as
  production. Recorded in `clippy.toml` where the knobs are, because that file
  previously claimed otherwise.
- **gradle need not be on `PATH`** — `make apk GRADLE=…` names one. Recorded in
  the Makefile and README.

Nothing here is a code change. It is the ledger's own upkeep, and it is filed
rather than done inline because a ledger edited as a side effect of other work
is a ledger nobody trusts.
