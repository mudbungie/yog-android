The phone deploy is currently hand-run env archaeology. Make it one command: 'make deploy-phone ADDR=<ip:port>' — build the arm64-v8a APK at the current tree, 'adb connect ADDR', 'adb -s ADDR install -r', and verify the install answered Success. Non-zero on any failure; the exit code carries the truth (same doctrine as yog's scripts/deploy/seat.sh).

Facts from the working manual run (2026-09-02, verified end to end):
- ADDR is an ARGUMENT and is never committed anywhere — the wireless-debug port rotates and the address is a routable tailnet IP the leak rules refuse; severability, same as seat.sh's HOST.
- ANDROID_HOME must be stated: the SDK resolves at the conventional user location but nothing exports it. The target should default it the way the screens target already defaults the sdkmanager path, overridable.
- gradle is not on PATH on this box; a working distribution lives under the gradle wrapper dists cache. Have the target resolve GRADLE: PATH first, else the newest bin distribution under the user's wrapper dists, else fail naming both probes. Keep the Makefile's existing GRADLE ?= override semantics.
- 'adb connect' to an already-connected device says 'already connected' and exits 0 — do not treat the message as an error.
- Do NOT auto-walk screens or launch the app; install is the whole act. make screens stays the harness's own door.

Honest limit to state in the target's comment: this is push-on-demand, not unattended CD — the wireless-debug port rotates on re-pair/reboot, so the address is per-run operator input by nature.

Verify premises against the tree (Makefile apk/screens targets) before editing.
