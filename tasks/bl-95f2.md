Seen on a real device at the current release.

1. A row whose name carries a machine qualification is long enough that the line is elided before the state at its end, so the two rows that most need it cannot be told signed-in from not. Put the state where it cannot be cut: its own line, or ahead of the name.

2. A pasted-code sign-in opens the vendor page in the phone's browser. When that browser holds no session with the vendor, the page asks for a login of its own first (an emailed link, here), which reads as the sign-in having failed. The seat cannot know this in advance; one plain sentence under the open control saying the page may ask you to log in first, and that the code comes after, is enough.

Tested by: a snapshot of the list with a qualified row at phone width showing its state; the sentence present while a run waits for a code.
