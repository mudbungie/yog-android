Seen on a real device at the current release.

1. A row whose name carries a machine qualification is long enough that the line is elided before the state at its end, so the two rows that most need it cannot be told signed-in from not. Put the state where it cannot be cut: its own line, or ahead of the name.

2. A pasted-code sign-in opens the vendor page in the phone's browser. When that browser holds no session with the vendor, the page asks for a login of its own first (an emailed link, here), which reads as the sign-in having failed. The seat cannot know this in advance; one plain sentence under the open control saying the page may ask you to log in first, and that the code comes after, is enough.

Tested by: a snapshot of the list with a qualified row at phone width showing its state; the sentence present while a run waits for a code.

---

Further defects in the same pasted-code sign-in, found by driving it on a device:

3. The on-screen keyboard covers the paste field and the send button. Both must stay visible above the keyboard.

4. The Back key closes the sign-in screen and drops what was pasted along with the waiting sign-in. Back must not destroy a waiting sign-in's state.

5. A sign-in waiting for its code cannot be resumed: once the screen is left the only way forward is to start again, which mints a new URL and invalidates the code already fetched. Returning to the row while its sign-in still waits must show the same waiting state and accept the code. Read what the server offers first (REMOTE 8.3; the server parks the verifier for ten minutes) and prefer reading its state over holding a copy.

6. The keyboard's own paste key does nothing in the field; only the clipboard suggestion chip works. Ordinary paste must work.

7. A row not configured for pasted-code sign-in fails only on the vendor's page, in the vendor's words. If the reply already carries enough to know this, say it in the app; if it does not, record that and invent no wire.

Tested by: the snapshots above plus the waiting screen with the keyboard up, and unit tests for back, resume and paste.
