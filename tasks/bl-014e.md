Operator drove the GameActivity build on real glass: the glide TRAIL draws — so Gboard is in full-IME mode and the InputConnection is real — but committed text never reaches the egui field. Root cause read out of the source, not guessed: winit 0.30.13's android event loop matches only InputEvent::MotionEvent and InputEvent::KeyEvent; InputEvent::TextEvent has no arm, so everything the InputConnection commits (glide, and taps too once the IC is live) is dropped before egui. Two exits, both viable: (a) forkless — the app polls AndroidApp::text_input_state() per frame and diffs the GameTextInput buffer into egui text events (the spike now displays that buffer live to prove the text arrives natively); (b) clean — a winit patch translating TextEvent into Ime events, upstreamable, and the house's second upstream PR if filed. Gradle recipe pinned meanwhile: games-activity 4.4.0 + explicit appcompat, kotlin-bom to dedupe stdlib, activity class lives under the androidgamesdk package, never enable prefab. Same build also carries the first live-wire smoke hook: a dial button running the crate's real Seat on operator-staged material (DESIGN §5 channel 1, performed via the debug bridge).

The forkless bridge WORKS, with two findings that shape the real shell. (1) Dead end, measured: pushing synthetic events into egui's Context::input_mut mid-frame lands in input the frame already consumed — buffer filled, field never did. The working bridge applies the GameTextInput buffer's frame-to-frame diff DIRECTLY to the focused field's own String (append / shrink / rewrite), which the shell owns anyway; verified on-device — commits through the InputConnection now land in the field, suggestion strip live, and glide rides the identical commitText path. (2) Upstream android-activity 0.6.1 bug, pinned to the line: its GameTextInput conversion callback calls slice::from_raw_parts on the library's pre-IME buffer whose pointer is NULL; under debug-assertions the stdlib's null precondition check aborts as panic_nounwind inside the extern-C callback — instant close-on-launch. Release profile compiles the check out and len-0 is benign; the real fix is a one-line null guard upstream, a better first-patch candidate than the winit TextEvent arm since the bridge makes the winit patch optional. Residual risks for the shell: focus tracking is one frame stale, and buffer-vs-field state needs true mirroring (set_text_input_state on focus change) rather than diffing alone.

Cursor finding, fixed and verified on-device: an edit applied behind egui's back moves no caret — TextEdit's cursor lives in egui memory per widget id, so the bridge must store it too (TextEditState::load, set_char_range to the edit's end, store; fields get explicit ids so the bridge can address them). Bridge upgraded to a common-prefix diff (one edit covers append, backspace, and a composing rewrite). Verified: text lands AND the caret sits at the end. Fair operator question answered honestly: this is hard because the bridge routes around egui's own input pipeline — winit's missing TextEvent arm forces every downstream duty (text delivery, cursor, someday selection) to be re-done by hand; the upstream winit patch dissolves the whole bridge, which strengthens its case.
