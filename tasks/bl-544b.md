yog REMOTE §13.2 rules that an endpoint list must carry the OBSERVED endpoint, and §13.8 measured why: on a cellular path the observed one is the only one there is (the handset's own address is carrier-private). bl-066c ported yog's walk but deliberately skipped yog bl-efae's observed-address vote on the reasoning that the phone never uses it — true today, and that is the defect: the phone's sealed call (src/rendezvous) lists only the addresses it sends from, so on cellular the engine punches toward an address it cannot reach and the full-rendezvous rung can never succeed from the network the phone most needs it on.

Port yog bl-efae (yog 022253e0; src/dht/krpc.rs reads the reply's ip, both lengths; src/dht.rs observed() is a per-family majority vote over the last walk, a tie gives nothing, a walk that heard nobody clears it) and have the call builder append each observed address not already listed, at the phone's punch port — address only, never the observed port (yog REMOTE §13.2: trust port preservation; the carrier-NAT port-rewrite case stays open, §13.8).
