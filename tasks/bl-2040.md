REMOTE §4.2 minted a second certificate grade after this client's tool host
landed. **Foot grade** is *"the tool-host gestures and nothing else:
`advertise` (§5.1), `invocations` and `complete` (§5.3). No other `Query`, no
other `Action`."* And the sentence that measures it: *"A foot cannot ask about
the world: not the workspaces, not the board, not the trail, not a transcript.
It cannot act on the world: no message, no start, no stop, no ball, no config.
What it may do is answer for the machine it is: state what this box can run,
wait for work addressed to it, and hand back what happened. Note which of
§5.3's four verbs is absent — `invoke`, the asking side's. A foot is invoked;
it never invokes."*

The grade rides on the leaf (`CN=<client>, OU=foot`), issued out of channel,
and enforcement is the engine's — one raise at the chokepoint, in band, naming
the grade. So nothing here can *grant* itself anything, and this ball is not
about permission. It is about the app being **honest about which component it
is running**: a phone enrolled on a foot-grade leaf that runs the seat's
standing-question loop earns a refusal per pass, per question, forever, and
the operator reads a wall of sentences where a component boundary belongs.

§4.2 names the phone directly as the class this exists for: *"a foot is the
class most likely to run on a box the operator trusts least (a build machine,
a phone, a box in someone else's house)."*

So the foot bootstrap runs the three gestures and holds no seat: the standing
set is not asked, the chat screens are not reachable from it, and the gesture
surface it can spend is a closed set the type system states rather than a
convention the loop happens to keep.
