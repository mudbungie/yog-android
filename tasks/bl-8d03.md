Device leg complete on real glass. Verdict: egui viable, O1 ruled for egui/NativeActivity — soft keyboard appears on focus, IME text commits, Enter submits and dismisses, and the bottom-anchored composer rides above the keyboard once the IME inset is fetched by JNI (WindowInsets.Type.ime; 908px measured with keyboard up, tracked live). Crash ledger, all dodged app-side, none in egui: (1) Imagination-GPU Vulkan driver segfault in vkCreateGraphicsPipelines under egui-wgpu — GLES backend dodges it; (2) ndk_context context is the APPLICATION object, so Application.getWindow() throws and the pending exception aborts under CheckJNI — activity_as_ptr() is the real Activity jobject, and every failed JNI lookup needs exception_clear; (3) a first attempt read activity_as_ptr as an ANativeActivity struct and died on a misaligned dereference — the docs say it is the jobject itself. SDK 35 notes: edge-to-edge is forced, adjustResize is dead, content_rect never tracks the IME, and a flush-bottom widget sits in the gesture-nav zone where taps never arrive. Residual: composition/preedit (glide typing, autocorrect) needs a human pass on the installed spike; a failure there reopens the fork question only. Spike code stays out-of-tree at ~/dev/yog-android-spike until the shell ball mines it.
