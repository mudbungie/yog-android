Operator ruling 2026-10-08 reverses the naming half of yog bl-15bd: the app an operator runs on desktop and on Android — the user interface — is **lernie**, not yog. yog is the server.

Scope, deliberately narrow ("no other changes"):
- the launcher label (`app_name`), the eframe window name, the accessibility-service description
- every sentence an operator reads that names the app: the pocket notification, the Java bridges' refusals that say "open yog" / "Settings > Apps > yog", the notification-channel descriptions, the clipboard label
- README §1 and DESIGN §1/§9: the ruling amended in place, citing this ball

What stays, and why:
- `applicationId` / Java package `dev.yog`, the JNI class names, the crate and repo name, the notification-channel ids, thread names: DESIGN §9's own words — once an install channel exists the id is a one-way door, and the channel (§20) now exists. An installed phone keeps its update path; the label is what rebrands.
- the three component brands on the bootstrap screen (Lernie / Thrall / Yog): the server IS yog.
- the wire tags (`yog-enroll`, the rendezvous salt, `yog.rendezvous` log prefix): protocol, yog's to name.
- the transcript prefix `yog:` — the engine speaking.

Cross-stack: yog REMOTE §12.1 carries the 2026-08-30 ruling and is amended by a yog ball of its own; lernie and thrall only name the repo.
