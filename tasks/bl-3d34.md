The release workflow's `CI / android / apk` job runs `Cross-clippy (the host
gate cannot see this cfg)` — clippy against `x86_64-linux-android`, which is
the only place the `#[cfg(target_os = "android")]` half of this crate is
linted at all. It has failed on every push to `main` since the tokens restyle
landed, and the three steps after it — build the APK, sign it, attach it to
the release — never run. So the §20 channel publishes nothing, and the phone's
update row has nothing to offer whatever the version gate decides.

    error: field assignment outside of initializer for an instance created
           with Default::default()
      --> src/shell/theme.rs:57:5
    error: could not compile `yog-android` (lib) due to 1 previous error

`install()` builds `egui::Style::default()` and then assigns `text_styles`,
four `spacing` fields and `visuals` onto it. `clippy::field_reassign_with_default`
is `deny` through the manifest's pedantic tier, and the host gate cannot see
the site because the whole module is android-only — which is the exact gap
the cross-clippy step exists to close, doing its job on a tree nobody had run
it against.

## Done when

- `install()` builds its `Style` in one initializer (struct-update for the
  fields it does not set), and states nothing new.
- `cargo ndk -t x86_64 clippy --lib -- -D warnings` is clean; `make check`
  stays green.
- The next push to `main` runs the apk job through to *Attach the APK*.

## Note for whoever takes it

`--all-targets` under the android target does NOT compile: the `tools/*/tests`
modules import host-only items behind `cfg(not(target_os = "android"))`. The
workflow lints `--lib` and so should you; widening it is a separate question.
