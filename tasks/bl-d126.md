The finding: clippy::pedantic's format_push_string on the two push_str(&format!(..)) calls in src/shell/app/probe.rs — the row rectangle's, added by bl-f97c, and the mark's, which had ridden clean until the second copy of the shape appeared beside it.

Why the host gate could not catch it, and why the class is not android-specific: format_push_string is a plain pedantic lint the manifest arms everywhere. What the host cannot see is the FILE. src/shell.rs gates every platform module behind cfg(target_os = "android"), so 'cargo clippy --all-targets' on the host compiles none of those modules and has no line to lint. The only local reproduction is the invocation ci.yml runs — 'cargo ndk -t arm64-v8a clippy -- -D warnings' with ANDROID_NDK_HOME pointing at the pinned NDK — which reproduced both errors on the tip and is green after the fix. Folding that into 'make check' would make the local gate refuse on every box without an NDK, which is the reason the android leg is a separate CI job rather than a step of the gate; the residual is that the cfg'd half is linted only after a push.

The fix takes neither escape the lint offers. No inline allow (rule 5) and no manifest entry, because the lint is right; and not write!, its suggested replacement, which hands back a Result that cannot fail and that rule 4 forbids unwrapping. The push seam is dissolved instead: a field() helper spells one optional rectangle or the empty string, and the line is assembled by a single format!. One helper for the same reason spell() is one — two rectangles cross this channel and a second copy of the spelling would be a second answer.
