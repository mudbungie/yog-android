The wire gained a fact this client does not state and a corpus this client is
not judged by. Both are REMOTE §3, both landed upstream after this client's
codec did, and until they are here the app cannot talk to a post-split engine
at all — the engine refuses the connection before a gesture is decoded.

**The preface.** REMOTE §3: *"Every connection opens with a version preface:
each end writes one frame, `{"protocol": <integer>}`, before it reads the
peer's. Both write before either reads, so neither waits on the other and
there is no ordering rule to remember. `PROTOCOL` is `1`."* A mismatch is
fail-closed and the refusal names both versions and the remedy; a peer that
states no version is refused exactly as a peer of the wrong one. This client
writes its request and reads an answer, which is the pre-version era — an
engine reads that envelope where a preface belongs and refuses it.

So the transport writes its preface and its request in the same breath, and
confirms the engine's on the way to the answer (§3: it costs no round trip),
and the mismatch arrives at the caller as the one `Err(String)` every other
transport failure already arrives as.

**The corpus.** REMOTE §3 states what a client owes it, and the contract is
three rules: decode every frame in both directories into the client's own
types; round-trip what it emits (decode then re-encode returns the frame
exactly), *"a client that only ever sends requests still decodes the request
fixtures; that is what catches a field it drops on the way out"*; and *"a
shape a client does not implement is still one it must not misread, so
skipping a fixture is a decision recorded in the client, never a silent
pass."*

This client's codec is a slice — the chat loop plus the tool-host trio — of a
vocabulary of dozens of shapes. So the skip set is a table with a reason per
row, and it is checked in both directions: a shape listed as skipped that the
codec actually reads is as much a defect as a shape neither listed nor read.
A skipped shape must still be *refused by name*, never silently accepted.

The fixtures are vendored, because there is no published artifact and no
endpoint that serves them (§3). Vendoring means the copy can go stale, so the
replay pins the protocol version it was cut at and fails when the client's own
`PROTOCOL` moves past it.
