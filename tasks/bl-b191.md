Found via bl-78c2 (operator reported the popup defect against a 'context size dropdown'; the control in question is the effort selector — the misidentification is the evidence). The shell's three drop-downs: provider and model name themselves by their content; effort shows only low/medium/high/off with no visible label, so an operator cannot tell what magnitude it governs. Give it a name where the operator reads it, consistent with the tuning band's idiom and REMOTE sec 9.4's vocabulary (effort). Check the desktop seat's tuning pane for the wording precedent (lernie src/ui/tuning.rs labels its effort seats per role). Small ball; verify premises against the tree.

---

Premise verified against the tree. src/shell/controls/pick.rs shows a provider selector whose face is a provider name and a model selector whose face is a model name, each falling back to its own word when nothing is set; src/shell/controls/tune.rs's priority is a toggle_value carrying the literal word 'priority'. Only effort painted a bare value — its face was the level alone, falling back to the word 'effort' when unset, so the control named itself exactly when it had nothing to say and stopped the moment it did.

lernie's precedent (src/ui/tuning.rs) is a whole pane under a 'role tuning' heading, with four selectable seats per role and a checkbox whose const is the word 'priority'. There is no label to copy there — a pane names its controls by the heading over them, and a two-control band under a composer has no heading — so what the precedent settles is the vocabulary, not the layout: the word is REMOTE sec 9.4's 'effort', spelled the same on the face as on the wire.

The change: the face reads 'effort: <level>' once a level is standing and keeps the bare word when none is, so the name is present in both states; one control, one act tag, no new widget for the parity inventory to account for. The width class moves 76 -> 132 so the face is sized for the longest thing it can say and does not resize under a pick — the button auto-grows past its min_size, and a growing face would shift the priority toggle beside it and run the text under the drawn caret. DESIGN sec 13.2's tuning-pair bullet now states the rule. No test moves: the file is cfg(target_os = "android") and coverage-excluded, so the verification is the cross-clippy CI runs plus a green make check.
